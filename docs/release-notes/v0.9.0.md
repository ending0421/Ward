# Release v0.9.0

> **拒绝作答的载荷不得自证成功**：issue #17 现场——消费方只解析 stdout 时，
> "没查成"与"查了没重复"在 JSON 层面字节级同形，200 条里误读 143 条。
> 本版让退出码、信封与字段说同一句话，并顺手补上 `spot-file` 的同类漏洞。

## Highlights

- **exit 3 的载荷不再携带伪造默认值（#17）**：`low_confidence` 与
  `query_specificity` 改为可缺席字段——无法作答时**字段缺失**（不是 `false` /
  `0.0`），可作答时与原契约完全一致；新增载荷级标记 `cannot_answer: true`，
  判定与 exit 3 规则**同源**（`index_state` ∈ missing/empty ∨ `stale_severe`），
  由引擎统一给出，CLI / MCP / 退出码不可能再各自漂移；
- **信封对拒绝作答说 `ok: false`（#17）**：两侧共用 `Envelope::refused`——
  `ok: false` + `error`（人类可读原因）+ **保留 data**（载荷本身就是解释：
  `index_state` / `cannot_answer`）。MCP 没有退出码，`ok` 是它唯一的机器信号；
- **`spot-file` 补上同类漏洞（#17 同类）**：报告新增
  `index_state: missing|empty|fresh|stale|unchecked`。此前"仓库没索引（fail-open）"
  与"这次写入没有新增/变更符号"返回的报告**完全同形**，hook 消费方无法区分；
- **快速路径仍是诚实作答**：`--quick`（`index_state: unchecked`、低特异度）保持
  `low_confidence: true` + `cannot_answer: false`——它测过，只是结论弱；
- **verdict 类命令保持原语义**（非目标，文档写明）：`form-check` /
  `catch-run --full` / `compat-check` 在 exit 1/2 时仍是 `ok: true`，因为它们的
  载荷**就是答案**（`verdict: fail|unknown` 是计算结果，不是模板默认值）——
  消费方读 `verdict`，不读 `ok`。

## Breaking Changes

- `SpotResult.low_confidence: bool` → **`Option<bool>`**，`SpotResult.query_specificity:
  f64` → **`Option<f64>`**（均 `skip_serializing_if = "Option::is_none"`）：
  Rust 消费方需按 `Option` 迁移；`None` 的语义是"从未计算过，不要采信"，
  绝不要 `unwrap_or(false)`；
- 新增 `SpotResult.cannot_answer: bool`、`SpotFileReport.index_state: String`
  （serde 默认：`false` / `"unchecked"`，旧 payload 可反序列化）；
- `spot --json` / MCP `spot` 在拒绝作答时 `ok: false`：只判断 `ok` 的消费方
  现在会正确地看到失败（这正是本版的目的）。退出码 3 的触发条件**未变**；
- 索引 schema 仍为 **v9**，指纹空间未变——从 v0.8.0 升级不需要重建索引。
