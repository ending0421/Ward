# Release v0.3.0

> 无感化与治理数据保全版：Ward 从"手动运行的工具"变成"装上就忘的后台系统"。
> `ward daemon` + `ward service install` 让索引/推断/快照/周报全自动；
> 同时修复了 schema 升级清空治理数据的缺陷，并让重复聚类豁免测试代码。

## Highlights

- **无感模式 `ward daemon`**：后台常驻——文件变更即增量索引、HEAD 变更即
  推断采纳、每日快照、每周 jscpd/聚类/校准建议自动写入 `.ward/metrics.jsonl`。
  唯一保留的人工环节是黄金集标注（人类判断的天性，不可自动化），daemon 会
  持续提醒待标注数；
- **`ward service install/uninstall`**：一键把 daemon 装成 macOS launchd
  LaunchAgent（RunAtLoad + KeepAlive）或 Linux systemd 用户单元，
  `--dry-run` 可预览单元文件；开机自启、崩溃自愈；
- **治理数据跨版本保全（F1 修复）**：此前 schema 升级会整库重建并**清空
  advisories/labels/snapshots/contract_runs**——治理数据恰恰是最不可再生的
  资产。现在重建只清派生表（符号/块/边），治理表完整保留；
- **重复聚类豁免测试代码**：测试函数结构近重复是**设计使然**，此前把
  38x/32x 的测试簇当"重复债务"报出。新增 `in_test` 标记（schema v5，
  `#[cfg(test)] mod tests` 与 `tests/` 路径双识别）+ `clusters.exclude_tests`
  配置（默认开），聚类信号从此聚焦真实重复；
- **指标基线正式启动**：`docs/metrics/` 记录首测基线（jscpd 2.60% 重复率、
  491 符号、176 测试），此后由 daemon 自动积累趋势。

## Breaking Changes

- **索引 schema v4 → v5**：symbols 表新增 `in_test` 列。F1 自动重建
  （约 1s @ 500 符号），且本版起**治理数据在重建中保留**（见上）。
- 新增配置节：`[clusters] exclude_tests = true`（默认豁免测试代码，
  关掉可恢复旧行为）。
- `ward daemon` 为长驻进程，日志输出到 stdout；经 `ward service install`
  安装后统一写入 `~/.ward/daemon.log`。

## Features

### 无感后台（新）

- `ward daemon --repo . [--interval-secs 300]`：watcher 去抖 → 增量索引；
  HEAD 轮询 → `ward infer`；日切 → 快照；周切 → jscpd + 聚类 + 校准建议，
  全部追加 `.ward/metrics.jsonl`（JSONL，坏行跳过）；
- `ward service install --repo . [--dry-run]` / `ward service uninstall`：
  launchd（macOS）/ systemd user unit（Linux）安装与卸载，幂等。

### 治理数据保全（修复升级为特性）

- `Store::reset` 重建时以 `ward_bak_*` 临时表搬迁 advisories/labels/
  snapshots/contract_runs 四张治理表；派生表照旧清空重建。

### 聚类测试豁免

- 提取器追踪 `#[cfg(test)] mod tests`（attribute 是兄弟节点，经
  `prev_sibling` 识别）与 `tests/` 路径，符号打 `in_test` 标记；
- `cluster_duplicates_with(store, threshold, exclude_tests)` 供配置驱动，
  报表与快照同步遵循该开关。

## Fixes

1. **schema 升级清空治理数据**（本版核心修复）：v0.2.0 升 v0.1.x 时
   advisories/labels 全灭——这正是我们 dogfood 数据丢失的根因；
2. attribute_item 与 mod_item 的兄弟关系识别（此前 doc-comment 检测
   同源问题，测试模块识别沿用 `prev_sibling` 模式）。
