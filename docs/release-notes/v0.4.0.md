# Release v0.4.0

> 多语言版：五门语法从"只索引"变成"全链路"——Kotlin/Swift 的签名查询
> 现在能给出强指纹证据，`languages` 配置从惰性字段变成真正的索引门控，
> 并修复了社区 PR 报告的管道死锁（大输出被误判超时）。本版同时吸收
> 上游 issue #2 与 PR #1 的全部反馈。

## Highlights

- **Spot 查询侧五语法**：此前 `ward spot` 的 proposed signature 写死用
  Rust 语法解析——Kotlin/Swift 签名查询静默退化为纯 BM25（textual，永不
  强提示）。现在自动尝试五种语法（Rust 优先，向后兼容），按"首个命名子
  节点是否为该语言符号节点"判定归属，无错解析优先；CLI 与 MCP 增加
  `--language` / `language` 参数强制覆盖（issue #2）；
- **Kotlin 函数体字段修复**：tree-sitter-kotlin 不在声明节点上声明
  field，导致签名指纹把函数体一起算进去——签名查询相似度只有 ~0.83，
  掉出强档。`LanguageSpec` 新增 `body_field`/`body_kinds` 表驱动解析，
  Kotlin 签名查询恢复到 ≥0.92 强档；
- **`languages` 真门控**：`.ward/config.toml` 的 `languages` 此前完全惰
  性；现在真正按名单过滤索引（大小写不敏感，未知名告警不报错），默认
  全部五门语言——无配置的多语言仓库行为不变；
- **管道死锁修复（社区 PR #1，已合并）**：`run_with_timeout` 此前等子进
  程退出后才读管道——输出超过 64KiB 管道缓冲时子进程永远卡在
  `write()`，真实通过被误报为 600s 超时。现在从 spawn 起就用读线程排
  空，附 1MiB 输出回归测试。

## Breaking Changes

- 无破坏性变更。索引 schema 仍为 v5，配置无格式变更。
- 行为变化（有意为之）：显式写 `languages = [...]` 的仓库，名单之外的
  语言文件将不再进入索引（此前该字段被静默忽略）。如需全量索引，删除
  该字段（默认五门语言）。

## Features

### Spot 多语言查询（`ward spot --language`）

```bash
# Kotlin 仓库：签名语言自动检测（也支持 --language kotlin 显式指定）
ward spot --repo . \
  --intent "防抖函数，支持 leading/trailing" \
  --signature "fun debounce(f: (Long) -> Unit, ms: Long): Unit"
```

- MCP `spot` 工具同步增加 `language` 参数；`proposed_signature` 不再限
  定 Rust；
- 检测规则：语法逐门尝试 → 首个命名子节点必须是该语言的符号节点（或
  query-alias 节点，保留 Rust 签名片段的宽容解析）→ 无错解析优先 →
  无任何语法接受则不给指纹证据（F3，宁缺毋假）。

### 语言门控（`.ward/config.toml`）

```toml
languages = ["rust", "kotlin", "swift", "java", "objc"]  # 默认全部五门
```

## Fixes

1. **管道死锁**（#1，Karl.Lyu 报告并修复）：子进程 stdout/stderr 从
   spawn 起由读线程排空；仅在子进程确定被收割后 join——真实通过不再被
  误判超时；
2. **Kotlin 签名指纹含函数体**：`LanguageSpec::body_child` 按 field →
   kind 回退解析 body（Kotlin 用 `function_body` kind），
   `index`/`signature_simhash`/replay `signature_hash` 三处统一；
3. **README 与实现不符**（#2）：MCP 工具表补全为 10 个工具；状态表补充
   查询侧覆盖说明；新增配置文档段。
