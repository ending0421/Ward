> FFI 导出面有了独立守卫、UDL 接口契约进索引进 Replay、monorepo

## Highlights

- **api_compat 三语言真裁决**：按构建系统自动选工具——Rust →
  cargo-semver-checks（原有）；Gradle → `./gradlew apiCheck`
  （binary-compatibility-validator，任务缺失=接线缺口=unknown，
  绝非假 fail）；SwiftPM/Xcode → **swift-api-digester**（基线 worktree
  dump + 工作树 dump + diagnose-sdk，macOS 工具链，其余平台诚实
  unknown）；Java（pom-only）→ japicmp 需显式新旧 jar，诚实 unknown；
- **FFI 导出面守卫（自研薄层，P4 例外）**：`extern "C"` 面是生成绑定
  的契约，三个生态工具各自都看不见。`ward compat-check --ffi` 拿
  nm 符号表对比**形态无关的清单**（`ffi.manifest` 配置 / `ffi/`、
  `include/` 自动探测 / 缺失则诚实 unknown）：removed=红，added=清单
  漂移警告。spec 新断言 `ffi_compat`，`form-check --ci` 外环裁决；
- **UDL 契约进三线**：UniFFI UDL 无 tree-sitter 语法（已核实），薄
  自研提取器覆盖六类结构——UDL 定义入索引（`language: "udl"`，
  契约指纹对注释/空白不变、对字段重命名敏感）、Replay 产出
  SignatureChanged 级变更、任何 .udl 改动挂 HIGH 风险标记
  "绑定是生成物，必须重新生成并人审"；
- **monorepo 模块作用域（§2.6）**：symbols.module（Cargo 包名 /
  Gradle 模块目录 / SwiftPM 包目录 / 顶层目录回退），spot 支持
  `--scope`/MCP `scope`，hook 自动按文件归属过滤——Rust 核心与
  Kotlin 包装层不再互相喂误报；构建产物目录（target/build/.gradle/
  DerivedData/.build）与构建清单文件（build.gradle.kts 曾被当
  Kotlin 源码索引）默认忽略；
- **M3 按语言选形**：内环 cargo check / gradlew classes / swift
  build，外环沙箱镜像矩阵 rust / gradle:8-jdk21 / swift；Xcode 为
  macOS runner 原生形态（CI apple-smoke），诚实 unknown 不硬跑。
