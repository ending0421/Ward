# Release v0.8.0

> **召回保真里程碑**：把"重复检测到底看见了什么"补齐。五个 issue
> （#12–#16）全部来自同一份 **97,743 符号**部署的现场回测，主题一致：
> 护栏说"没有重复"时必须真的看全了（裸类型参数、逐字复制、worktree
> 未合并来源），说"有重复"时必须给出可执行、可审计的处置闭环
> （转化率、标注、降级理由）。

## Highlights

- **裸类型参数不再被丢弃（#16）**：`parameter_types` 的过滤器把
  无子节点的 identifier 类节点全删了——tree-sitter-rust 里裸类型
  `type_identifier` 正是这一类，于是 `fn g4(x: Canvas)` 的特异度算成
  0.0（应为 1.0），被误判低置信度、gate 直接跳过；混合签名分母缩水
  （`0.50` 应为 `0.67`）。现场 2 个月 gate 语料中 **8% 的签名**命中
  此坑。现在只跳过"参数名"（参数节点里的第一个 identifier），包装
  与否不影响比值；
- **逐字复制必须自匹配（#15）**：`--body` 传入的完整函数此前只进块层，
  指纹仍用签名算，且被排除的函数体仍留在**父节点的 children 特征**里
  ——逐字复制只能到 `near 0.89`，大仓库里同形兄弟会把原件挤出 `top_k`。
  现在特征集在排除 body 时同步从父节点特征中移除，`spot` 也优先用
  **可完整解析的声明**作指纹源：纯签名 → 原件 ≥0.99，完整函数 →
  `structural 1.0`，签名+精确 body → `structural 1.0`；
- **worktree 未合并来源可见（#12）**：linked worktree 里先写出来的重复
  此前对主 checkout 完全不可见。新增按需收集（`ward index
  --include-worktrees` / `[index] include_worktrees`）+ schema v9 的
  provenance 列（`worktree` 根 + `worktree_branch` 分支）：命中带
  `未合并来源（worktree <目录>@<分支>）（#12）`，行号与 per-file 新鲜度
  都按 worktree 根解析（未合并内容不会把每条 advisory 拖成 stale），
  worktree 删除后条目整批清理；**PostToolUse hook 始终开启收集**，
  静默路径无需人工干预；
- **转化率入治理报表（#13）**：`ward stats --funnel` 把每条 advisory
  分桶为 `acked` / `reused` / `rewritten` / `pending` / `abandoned`
  （按周 cohort），M6 clusters 给出合并建议——护栏的"建议 → 决策"
  闭环第一次有可读数；
- **MCP 补齐（#14）**：新增 `ack`（登记决定）与 `infer`（回填处置）
  两个工具（共 12 个），Agent 不必离开 MCP 就能闭环 ack/处置。

## Breaking Changes

- **指纹空间变更**：`node_feature_excluding`（父节点特征不再包含被排
  除的 body）与 `parse_complete_declaration`（指纹源选择）会改变
  L1/L2 分数分布 → **历史校准与阈值假设需重新对表**；`simhash` 存储值
  随下一次 `ward index` 全量刷新，旧索引与新索引的分数不可混比；
- `SpotResult` 契约扩展：新增 `worktree_symbols`；`SpotMatch` 新增
  `worktree` / `worktree_branch`（全部带 serde 默认，旧 payload 仍可
  反序列化）；
- 索引 schema v8→**v9**（`symbols.worktree` / `symbols.worktree_branch`
  + 索引）：F1 自动重建，治理表（advisories/labels/snapshots/
  contract_runs/acks）保全，仅损失一次全量索引时间；
- 特异度语义修正会让一部分**此前被静默跳过**的签名重新进入判定
  （这正是 #16 的目的）：低置信度比例下降，gate 看到的命中数上升。
