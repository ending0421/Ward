# Release v0.4.1

> 两个 hotfix（issue #3 / #4）：把 M1 spot 从"intent 措辞决定召回"的
> 隐性随机，变成 signature/body/index 的纯函数；并统一 CLI 与 MCP 的
> JSON 信封。这一版没有新功能——按里程碑发布纪律，0.4.x 只出 hotfix。

## Highlights

- **near 命中集合指纹化（#3）**：此前 near 候选集来自"intent + 签名"
  的 BM25 top-50——intent 措辞一变，候选集就变，强结构命中可能整体
  消失（hook/CI 等没有"好 intent"的自动化消费者召回随机）。现在签名
  可解析时**全表 sig_simhash 汉明扫描**（10⁵ 符号 ≈ 1-3ms，F11 预算
  内），near 集合成为 signature/body/index 的纯函数；intent 只影响
  textual 通道（无指纹证据时）与并列排序。回归测试锁定：同一签名两
  种 intent → near 集合严格相等；
- **CLI/MCP JSON 信封统一（#4）**：两个表面此前返回不同形状（MCP
  `{ok,data}`，CLI 裸 payload），按信封写成的消费者对 CLI 输出会
  **静默读出空集**——护栏工具最坏的一类失败。现在 `ward <任意子命令>
  --json` 与 MCP 工具共享同一 `{ok, error?, data?}` 信封（ward-core
  单一实现，双表面共用）；
- **`ward spot --body-file <路径>`**：hook/CI 上下文里大函数体不再撞
  argv 的 ARG_MAX 限制（与 `--body` 互斥）。

## Breaking Changes

- CLI `--json` 输出形状变化：顶层从裸 payload 变为 `{ok, data}` 信封
  （与 MCP 对齐）。**迁移**：把 `.matches` 改为 `.data.matches`（或
  `jq '.data.matches // []'` 的 `.data` 前缀）。本仓库的
  verify-meaningful、CI dogfood、hook 脚本已同步迁移。

## Fixes

1. near 召回随 intent 措辞翻转（#3）——见 Highlights；
2. CLI/MCP JSON 形状不一致导致静默空集（#4）——见 Highlights；
3. 顺带：near 扫描路径替代了逐查询 BM25 召回，10⁵ 基准 spot p99
   93ms → **73ms**（余量从 7% 升到 27%）。

## Testing / CI

- 新增：intent 不变性 e2e（#3 复现）、信封单测（ok/err 形状）、
  cli_smoke 全部 JSON 断言迁移到信封形状。
