# Release v0.3.1

> 远程诊断与反馈版：Ward 在别的机器上出问题时，能用它自己把问题报回来——
> 隐私脱敏的诊断包、单条 advisory 的完整复现上下文、以及一条命令开出
> GitHub issue。这是"Ward 自己报告自己的问题"的 dogfood 闭环。

## Highlights

- **`ward doctor`**：环境与健康探针——版本/平台/仓库规模/语言分布、
  索引与 spot 延迟实测、指标尾部与 daemon 日志尾部；**默认全脱敏**
  （无绝对路径、无源码片段、config 只留安全数值），`--include-*`
  三开关显式放开；
- **诊断包 `--bundle`**：一键写出可移植的 `ward-doctor-<ts>.json`，
  从另一台电脑拷回来即可复现分析；
- **`ward report <advisory-id>`**：单条 advisory 的完整上下文（查询、
  matches、双通道处置、黄金集标注），源码片段严格 opt-in
  （`--include-snippets`）；
- **`ward issue create`**：按标准模板（环境摘要 + 复现步骤 + **隐私确认
  清单**）生成 issue，复用 gh CLI 提交，诊断包经 **secret gist** 附带；
  **默认 dry-run**——不显式加 `--yes` 什么都不会发出去（§7：数据不出
  机器，上传永远是显式动作）；
- **修复**：`snippet_of` 此前按进程 cwd 解析相对路径，`--repo` 指向别处
  时会读错文件——现以仓库根解析；doctor 的符号数改用 store 总量
  （增量报告的 delta 在未变更仓库上恒为 0）。

## Breaking Changes

- 无（索引 schema 仍为 v5，配置无破坏性改动）。

## Features

### ward doctor / report / issue（新）

- 三个命令构成完整的"异地反馈"工作流：
  1. 另一台机器：`ward doctor --repo . --bundle` → 拷回 `ward-doctor-*.json`；
  2. 本机：`ward report <advisory-id> --include-snippets` 复现单条问题；
  3. 本机：`ward issue create --title ... --bundle <包> --yes` 开 issue。

## Fixes

1. `snippet_of` 路径解析以仓库根为准（此前依赖进程 cwd，跨目录使用会读错文件）；
2. doctor 符号数用 store 总量（增量索引 delta 恒 0 的误导）；
3. 仓库名解析：`--repo .` 时 canonicalize 出真实目录名（此前显示 `?`）。
